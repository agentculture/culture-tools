# Design — tools.culture.dev

The package index for agent-first CLI tools that **conform to the AgentFront
contract**. This document is the architecture of record; it captures the
decisions made while scoping the build so future work stays on-rails.

## What it is

`tools.culture.dev` is a **static** site with two faces:

1. A **discovery landing** (human + agent readable) showcasing the agent-first
   tools in the AgentCulture ecosystem — what each does, how to install it, where
   its source lives.
2. A **PEP 503 simple index** (`/simple/`) so the catalog is machine-installable
   the same way a PyPI index is.

Membership is **earned, not declared**: a tool appears on the index *iff* it
passes the AgentFront contract (see [Conformance gate](#conformance-gate)). The
index's job is to *certify* the contract, which is why this is a curated index
and not a mirror of PyPI.

## Locked decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Functional shape | Catalog **+ static `/simple/`** index. No wheel hosting in v1 — `/simple/` links point at each tool's real wheels on PyPI. | Fully static → trivially CDN-hostable; no storage/upload pipeline to operate. |
| Repo location | **In this `culture-tools` repo** — Astro site under `site-astro/`, catalog generator in the `culture_tools` package. | One repo; `culture-tools` *is* the index's backend (per its own description). |
| Catalog source | **AgentFront metadata** — generated by running each tool's `learn` / `overview` / `doctor` `--json` verbs, plus `culture.yaml` + `pyproject.toml`. | Self-describing and self-validating; the index dogfoods the very contract it certifies. New conformant tools surface from their own output. |
| Conformance gate | **Delegate to `agentfront cli doctor <repo> --strict --json`** (`healthy == true`). | `agentfront` (formerly `teken`/`afi-cli`) is the canonical rubric authority; we don't reinvent the verdict. |
| Front-end style | **Astro static, Anthropic-cream (light) + katvan-green (dark)** — catalog-first card grid. Took `../katvan`'s Astro/CF-Pages *structure*; light mode wears the warm-cream palette of the sibling `agentic-human` / `humanic-ai` sites, dark mode wears katvan's terminal green (`#41d67a`). | Registry scannability + AgentCulture house look; the two family aesthetics meet in one site. |
| Hosting (v1) | **Cloudflare only** (CF Pages, static), domain bound via `../cultureflare`. | Simplest near-zero-cost static host; DNS for `culture.dev` already lives at Cloudflare. |
| Hosting (later) | AWS **S3 as the durable DATA / backup / deep-cache tier** behind the CF edge; recent/hot load served from Cloudflare. | Deferred; the artifacts are plain files, so adding an S3 origin/backup later is additive, not a rewrite. |

## Conformance gate

A candidate tool is **in** the index when:

```bash
agentfront cli doctor <tool-repo> --strict --json   # → {"healthy": true, ...}
```

`agentfront cli doctor` is a hybrid auditor over the **seven-bundle rubric** —
`structure`, `learnability`, `json`, `errors`, `explain`, `overview`, `doctor`
(static repo checks + black-box subprocess probes of `learn` / `--json` /
error-discipline / `explain`). The generator records the verdict (and the failing
bundles, when not healthy) so the index can show a conformance badge and exclude
non-conformant tools without hand-curation.

## Data flow (v1, all-Cloudflare static)

```text
candidate tools (manifest: name → repo + pypi name)
      │
      │  agentfront cli doctor <repo> --strict --json   → conformance verdict
      │  <tool> learn --json / overview --json           → purpose, command map
      │  culture.yaml                                     → nick / backend / model
      │  pyproject.toml                                   → version, dist name, homepage
      ▼
  culture-tools index build         (new noun; zero-dep Python, this package)
      │   emits:
      │     site-astro/src/data/catalog.json            (Astro consumes this)
      │     site-astro/public/simple/index.html         (PEP 503 root)
      │     site-astro/public/simple/<pkg>/index.html   (dist links → PyPI)
      ▼
  site-astro  (Astro, dark-terminal start) — npm run build → dist/
      │   landing + /tools/<name> pages + /simple/ passthrough
      ▼
  Cloudflare Pages (builds site-astro/, serves dist/ static)
      │   cultureflare: cf-pages-project-create + cf-pages-domain-add tools.culture.dev
      ▼
  https://tools.culture.dev
```

The `/simple/` HTML is generated by porting `../auntiepypi`'s small, pure-Python
index pieces (PEP 503 name normalization + the index/project HTML templates) into
a **static emitter** — cite-don't-import, to preserve this package's zero runtime
dependency property. We do not run auntiepypi's live `http.server`.

## The new CLI surface (`culture-tools index`)

Follows the repo's established agent-first patterns exactly (a `register()` module
under `cli/_commands/`, `--json` everywhere, `CliError` propagation, an `explain`
catalog entry, and — because `index` is a noun with action-verbs — an
`index overview` to satisfy the rubric's `overview_cli_noun_exists` check):

- `culture-tools index build [--out DIR]` — generate `catalog.json` + the static
  `/simple/` tree from the manifest.
- `culture-tools index check [TOOL]` — run the conformance gate for one/all tools
  and report the verdict (no emit).
- `culture-tools index overview` — describe the index noun's surface.

## Milestones

Each milestone is one PR (this repo bumps the version every PR; the
`version-check` CI job enforces it).

- **M1 — AgentFront catalog generator.** The `index` noun: conformance gate
  (delegates to `agentfront cli doctor`), tool introspection → catalog entries,
  the static PEP 503 `/simple/` emitter, a starter manifest, `catalog.json`
  output, tests, explain entry. *Hosting-independent; the durable core.*
- **M2 — Astro site. ✅ Done.** `site-astro/` (Astro 6, `output: 'static'`, no
  adapter) consuming `catalog.json`: a cream catalog landing (hero + install
  one-liner + certified-tool grid + a roadmap section listing pending candidates
  with the bundles they still fail), per-tool detail pages (install, repo/PyPI
  links, command surface), conformance badges, and a light/dark toggle.
  `scripts/sync-catalog.sh` runs `culture-tools index build` and distributes its
  output → `src/data/catalog.json` (imported, typed) + `public/simple/` (served
  verbatim). Theme is Anthropic-cream, light by default.
- **M3 — Cloudflare deploy lane.** *In progress.* Deploy provisioned by
  cultureflare (issue #47): a CF Pages project `tools-culture-dev` (git-integration,
  option 1 — no secrets) builds `site-astro/` from `main` on push and binds
  `tools.culture.dev`. **Catalog-refresh CI landed** —
  `.github/workflows/catalog-refresh.yml` regenerates the committed catalog from
  live conformance via `index build --repos-dir <cloned siblings>` and opens a PR
  (human-reviewed before a merge triggers the rebuild). Still open: `_redirects`
  for a pip-resolvable `/simple/`.
- **M4 — Polish.** Agent affordances: `llms.txt`, markdown twins, sitemap,
  conformance badges, SEO. (S3 durable tier can land here or later.)

## Open items (deferred, not blocking M1)

- **Candidate discovery.** v1 uses a small hand-maintained manifest of tools to
  index; auto-discovery from the `agentculture` GitHub org / PyPI is a later
  enhancement.
- **CI introspection environment.** Generating the catalog in CI needs each tool
  installed (`uv tool install`) or its repo checked out so `agentfront cli doctor`
  and the `--json` probes can run. Resolved in M3.
- **S3 durable tier.** Wiring S3 as backup/deep-cache behind Cloudflare — M4+.
